# Attack Classes for Security Reviews

What to hunt for, by domain, once you know a target's architecture and trust boundaries. Adapted from the companion files of Cloudflare's [security-audit skill](https://github.com/cloudflare/security-audit-skill) (MIT licence, commit `c1c8a8c`, read on 2026-10-22). The class names are theirs; the one-line prompts are condensed. Use them with the OWASP Top 10:2025 checklist in [rigorous-code-audit](../../rigorous-code-audit/SKILL.md) and the standards in [domain-standards.md](domain-standards.md).

A class is a question to answer with source evidence, not a finding. Every candidate still needs the boundary-and-result proof in [rigorous-code-audit](../../rigorous-code-audit/SKILL.md) section 4.

## Core classes (every target)

| Class | Ask |
| :--- | :--- |
| Injection | Does untrusted data reach a SQL, NoSQL, shell, template, path, header, LDAP or expression interpreter without binding or encoding? |
| Access control | Is authorization checked server-side for every action and every object, including list, export and bulk endpoints? |
| Resource and file handling | Path traversal (including symlinks and encoded sequences), SSRF (including redirects, DNS rebinding and URL-parser differences), unsafe deserialization, archive extraction (zip slip), temporary files, check-then-use races on files |
| Cryptography and secrets | Weak randomness for tokens and keys; secrets in code, logs, URLs or responses; broken key derivation, missing MAC checks, nonce reuse; variable-time comparison; ECB, unauthenticated encryption, static IVs; an error path that falls back to no cryptography |
| Business logic | Skipped, replayed or half-failed workflow steps; races with business impact (double spend, double approval); negative, zero, overflowing or coerced quantities; a restriction on one operation bypassed through another; stored data trusted because it was validated on a different path |
| Feature abuse and data leakage | Export or backup as exfiltration; import or restore as injection; search, filter and sort as oracles; enumeration through different errors, timings or status codes; preview, draft and cache leakage |
| Chained vulnerabilities | Multi-step boundary failures; a guarantee component A provides that is weaker than what component B assumes; second-order use (stored data later used as a path, URL, template or query); capabilities that grow after delegation, refresh or role change; stale state across revoke, expiry or soft-delete windows |

**Obvious things sweep**, done literally because everyone assumes someone else checked: hard-coded credentials and keys; security `TODO`/`FIXME` notes; debug or development modes that can be enabled in production; seed or example credentials that work; unprotected `/debug`, `/admin`, `/metrics`, `/env`, `/.env` or `/config` routes; committed `.env`, `*.pem`, `*.key` or credential files and gaps in `.gitignore`; unpinned dependencies with known CVEs; `eval`, `exec` or dynamic imports fed by input; wildcard CORS, especially with credentials; cookies without `HttpOnly`, `Secure` or `SameSite`; open redirects through `redirect`, `next`, `url` or `return` parameters; plain-HTTP endpoints; stack traces or SQL errors in production responses. Trace each hit before reporting it: a missing cookie flag matters only if the cookie is sensitive and scripts do not need it.

## Domain companions (choose those the architecture needs)

| Domain | Classes |
| :--- | :--- |
| HTTP protocol and authentication | Request framing and desynchronization (request smuggling); web cache poisoning through unkeyed input; cache deception and caching of private responses; trust in `Host` and forwarded headers; response-header injection; CSRF; session fixation and invalidation; cookie scope and transport; JWT verification and claim binding; OAuth/OIDC request and callback binding; SAML signed-object and assertion binding; MFA enrolment and assurance downgrade; step-up bypass; WebAuthn and passkey verification; account linking and identity collision; password reset and recovery; API-key scope, exposure and transport; certificate lifecycle fallback |
| Client side (browser) | DOM-based XSS; DOM clobbering; prototype pollution and gadget chains; cross-site WebSocket use; credentialed CORS trust; service-worker scope takeover and cache confusion; browser-storage disclosure and stale authorization; cross-context storage and broadcast confusion; XS-Leaks and cross-origin state oracles; window and opener disclosure; clickjacking; client-side navigation confusion |
| AI and LLM | Indirect prompt injection through retrieved content; cross-session or cross-tenant context bleed; persistent memory poisoning; prompt role and provenance confusion; tool-argument injection into a downstream sink; excessive agency and confused-deputy authority; approval prompts that do not bind the action actually executed; tool-schema and dispatcher disagreement; unbounded delegated loops; sub-agent and MCP trust inheritance; MCP server and tool identity confusion; MCP metadata treated as policy; insecure rendering of model output; extraction of sensitive context |
| Supply chain and release | Dependency source and namespace confusion; mutable or unpinned build inputs; generated-code provenance; secrets or extra files included in the build context; untrusted code in a privileged CI workflow; workflow expression injection; cache, artifact and workspace trust mixing; automation identity overreach; substitution between build and promotion; release authorization and signing gaps; update metadata and rollback confusion; plugin and extension trust expansion |
| Cloud and deployment | Workload identity overreach; cross-account or cross-tenant role confusion; authorization delegated to cloud metadata; reachable management planes; trusted-proxy and service-mesh identity bypass; reachable metadata and internal services (SSRF targets); host or control-plane capabilities in containers; admission-policy gaps; namespace and label trust; precedence drift between configuration layers; secrets shared across workloads; credential renewal falling back to unsafe paths; object-storage and signed-URL policy confusion; event-source identity confusion; edge and runtime boundary mismatch |
| Protocols, RPC and messaging | Message boundary and canonicalization disagreement; union, enum and default confusion; envelope and payload identity mismatch; interceptor versus method-path inconsistency; peer identity mapped to the wrong application principal; per-item and streaming authorization gaps; callback and reply correlation; topic and subscription scope; disclosure through dead-letter and retry queues; untrusted producers treated as control plane; duplicate delivery without idempotency; stale or out-of-order messages; acknowledgment before commit; partial multi-consumer transitions |
| Resource exhaustion | Superlinear parsing or regular expressions; decompression and representation bombs; query amplification; unbounded buffers and cardinality; leaked handles and temporary resources; work that continues after cancellation; expensive work before authentication; quota scope and reset gaps; worker and pool starvation; reachable fatal errors and deadlocks; retry storms and fail-open; poison records that block a queue; unsafe recovery |
| Data isolation and lifecycle | Missing tenant or owner filters; composite-key and namespace collisions; policy and query disagreement; signed references that reach too far; search, cache and index ACL drift; logs, analytics and traces as alternate readers; enumeration and aggregate oracles; export, backup and restore scope expansion; migrations that set unsafe owners or defaults; soft-delete bypass; stale authorization on derived copies; retention overrun; restores that reintroduce revoked state |
| Desktop, mobile and local IPC | Deep-link and custom-scheme ambiguity; app and account handoff confusion; file-open and intent authority; webview navigation reaching native bridges; over-broad bridges; webview file access; IPC peer authentication; claimed versus channel identity; exported Android components; privileged helpers as confused deputies; install and update path trust; local-file TOCTOU; credential-store boundaries; data left after logout, account switch or device restore |
| Memory safety and binaries | Out-of-bounds reads and writes; integer overflow, truncation and signedness; uninitialized data; use-after-free and double free; type confusion; reference-count and shared-state races; lock ordering; FFI pointer, length, ownership and layout contracts; unwinding across FFI; library and plugin search-order trust; unsigned artifacts; malformed binary metadata; JIT consistency; unload and teardown safety; kernel user-copy bounds and privileged interfaces ([language security](language-security.md)) |
