# v1.8.0 - Always Current: Dependencies, Tools and Patches
## Projects 24 v1.8.0: Always Current

Dependencies, tools and runtimes now stay current on their own: updates are checked every day, security patches arrive as soon as they are published, safe updates merge themselves once CI passes, and anything a bot cannot see is watched daily.

### Key Highlights
- **Daily Dependabot for every ecosystem**: npm, GitHub Actions, Docker and the CI's Python tools (moved to `.github/ci-tools/requirements.txt` so Dependabot can update them). Security updates skip the cooldown and arrive at once; version updates keep a 7-day cooldown against freshly compromised releases.
- **Auto-merge for patch and minor updates**: a workflow turns on auto-merge for Dependabot's patch and minor pull requests, but only when the base branch requires status checks, so nothing merges untested. Major updates wait for a person.
- **Daily freshness watch**: `scripts/check-freshness.mjs` reports pins Dependabot cannot see (gitleaks, the Python template's mypy, Ruff and pip-audit) and CI runtimes that are end-of-life or missing the newest supported release (Node.js and Python, from endoflife.date).
- **Daily advisory watch**: `scripts/audit-lockfiles.mjs` audits every lockfile even when nothing changed, failing on high or critical advisories; accepted risks need a reason and expire.
- **Python 3.15** added to CI and to the `ci-python.yml` template.
- **Rule 04, "stay current continuously"**, and new ci-cd-pipeline templates (daily `dependabot.yml`, `dependabot-auto-merge.yml`) bring the same setup to every project that uses the spec.

### Before it runs fully
- Turn on Dependabot security updates and "Allow auto-merge" in the repository settings, and require the `Validate` checks on `main` (SECURITY.md, maintainer checklist). Until checks are required, the auto-merge workflow stays off on purpose.
